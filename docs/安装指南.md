# Mac 安装指南（从零开始）

本指南安装的是 **Mac 本机 Docker 服务＋浏览器管理界面**。可创建双击启动的 Mac App 入口，无需 Apple 开发者账号。它不是 VPN 客户端，不会自动改变 Mac 路由，也不会修改原服务器或 Cudy。

## 1. 准备环境

建议预留至少 2 GB 内存及 5 GB 可用磁盘；第一次构建需要联网下载镜像和软件包。已在 Apple Silicon Mac 上验证，Intel Mac 尚未实机验证。

打开 Mac 的“终端”，检查 Git：

```bash
git --version
```

如果提示安装命令行工具，按系统提示完成安装；也可以运行 `xcode-select --install`。创建双击入口需要 Python 3，可用 `python3 --version` 检查。

### 方案 A：Docker Desktop（新手推荐）

1. 从 [Docker 官方网站](https://www.docker.com/products/docker-desktop/) 下载适合 Apple Silicon 或 Intel 的版本。
2. 安装到“应用程序”，启动 Docker Desktop，等待引擎运行。
3. 在终端确认：

```bash
docker info
docker compose version
```

### 方案 B：Colima

如果已安装 [Homebrew](https://brew.sh/)，可运行：

```bash
brew install colima docker docker-compose
colima start --cpu 2 --memory 2 --disk 20
```

本文命令默认用 `docker compose`。Homebrew 安装若提示没有 compose 插件，将后续命令中的 `docker compose` 换成 **`docker-compose`** 即可。项目自带启动脚本会自动选择这两种写法。

不要同时启动两套引擎来管理同一应用；`docker context show` 可查看当前连接的引擎。切换引擎后看不到原数据卷，并不表示数据已删除。

## 2. 下载代码

公开仓库可直接下载，不需要 GitHub 登录：

```bash
mkdir -p ~/Projects
cd ~/Projects
git clone https://github.com/boxie283555/meraki-split-console.git
cd meraki-split-console
```

后续命令均在此目录执行。也可用 GitHub 的 Code → Download ZIP，但建议使用 Git，便于后续更新。

## 3. 填写自己的组织和网络

首次安装执行：

```bash
cp .env.example .env
chmod 600 .env
open -e .env
```

在文本编辑器中修改并保存：

```dotenv
BIND_IP=127.0.0.1
CONSOLE_HOST=localhost
MERAKI_ORG_ID=你的组织数字ID
MERAKI_NETWORK_NAME="你的网络名称"
ENABLE_SCHEDULE=1
```

- **组织 ID** 是 Meraki API 的 organizationId，不是组织名称，也不一定等于浏览器网址里的标识。可向管理员索取，或从 Dashboard API 的 `GET /organizations` 返回结果取得。
- **网络名称** 必须与 Dashboard 一致，并在该组织下唯一；带空格时用引号包住。
- `BIND_IP=127.0.0.1` 表示仅本机访问，首次使用保持默认。
- `ENABLE_SCHEDULE=1` 启用日常刷新调度，不等于授权自动下发 Meraki 配置。设为 `0` 可关闭定时调度，保留手动操作。
- `.env` 不填写 API Key。首次登录后在界面中录入，密钥不会进入源码或镜像。

这些环境变量只在**新数据卷第一次初始化**时生成 `/data/config.json`。已经启动过的实例，再改 `.env` 中的组织和网络不会覆盖既有配置。详见后文故障排查。

## 4. 构建并启动

```bash
docker compose up -d --build
docker compose ps
```

第一次需要下载镜像，可能耗时数分钟。容器先显示 `starting`，随后应显示 `healthy`。

打开：**https://localhost:8443**。

首次证书由本机自动生成，浏览器可能提示证书不受信任。确认网址确实为本机 `localhost:8443` 后继续访问；不要改成 HTTP。如果浏览器不允许继续，需由管理员将本机证书加入信任，或配置可信证书。

## 5. 首次登录

默认用户名为 **admin**。初始密码是每次新安装独立生成的，用终端查看：

```bash
docker compose exec console cat /data/private/gui-initial-password
```

复制输出到登录页即可。不要把此输出、截图或数据备份发到公开仓库。关闭页面不会停止后台服务。

首次登录不要求先有 Meraki API Key；没有 Key 时，可以使用地址库等独立功能，但不能读取自己的 Meraki 配置。

## 6. 接入 Meraki

1. 在 Meraki Dashboard 由组织管理员启用 API access。
2. 在个人资料的 API access 页面生成自己的 API Key。
3. 在本平台“接入设置”中粘贴并保存 Key。
4. 等待刷新完成，在概览确认目标组织、网络和读取状态。

只读权限适用于查询及备份；下发规则需要相应写权限。如果组织配置 API 来源白名单，需要允许 **Mac 实际出网公网 IP**。

新实例默认没有自动下发授权。先查看差异和计划，确认目标网络后再手动下发。不要让旧服务器与新 Mac 实例同时管理同一网络的自动下发，否则可能互相影响规则归属。

## 7. 创建 Mac 双击启动入口（可选）

```bash
python3 scripts/install-mac-app.py
open "$HOME/Applications"
```

目录中会出现 **Meraki Console.app**，可拖到 Dock。双击会打开终端、启动运行环境及容器，并打开本机网页；它不是独立原生客户端。

入口引用当前源码目录。移动源码后，需要先将旧的启动入口移到废纸篓，再重新运行安装命令。不要删除 Docker 数据卷。Mac 关机或睡眠时不能继续执行后台任务。

## 8. 日常启动、停止与日志

```bash
# 启动已构建应用
docker compose up -d

# 停止，保留数据
docker compose stop

# 查看运行状态
docker compose ps

# 查看最近日志
docker compose logs --tail 100
```

后台任务日志位于容器 `/data/logs/`：

```bash
docker compose exec console ls /data/logs
docker compose exec console tail -50 /data/logs/meraki-split-preview.service.log
```

`healthy` 只代表本机 Web 服务可响应，不代表 Meraki Key、备份或下发已经成功，业务结果仍需在页面核对。

## 9. 更新版本

先等待所有备份、刷新、下发任务完成，并按下一节备份。然后执行：

```bash
git pull --ff-only
docker compose up -d --build
docker compose ps
```

数据卷会保留。不要重新复制 `.env.example` 覆盖自己的设置。若 `git pull` 提示本地修改冲突，先保留并合并修改，不要强制覆盖。

## 10. 备份和换电脑

应用的 **Docker 数据备份** 与界面中的 **Meraki 配置快照** 不同：前者包含登录信息、API Key、证书、计划、规则归属、DNS及任务状态；后者用于核对和恢复Meraki可读取配置。

先等待任务结束，再停应用创建完整数据备份。以下命令在源码目录执行，使用唯一文件名避免覆盖旧备份：

```bash
umask 077
backup_file="$HOME/meraki-console-data-$(date +%Y%m%d-%H%M%S).tgz"
docker compose stop
docker compose run --rm -T --no-deps --entrypoint tar console -C /data -czf - . > "$backup_file"
tar -tzf "$backup_file" >/dev/null
docker compose up -d
```

确认命令成功且文件非空。备份含敏感数据，私下保存，不要上传GitHub。**不要使用 `docker compose down -v`，它会删除数据卷。**

新电脑先完成Docker安装、下载代码、准备`.env`，再在**空白的新数据卷**恢复：

```bash
docker compose build
# 将下面文件路径替换为实际备份路径；不要恢复到有新数据的旧卷。
docker compose run --rm -T --no-deps --entrypoint tar console -C /data -xzf - < "$HOME/meraki-console-data-备份时间.tgz"
docker compose up -d
```

恢复后沿用原账号密码及组织配置。迁移前应停止旧实例，避免双实例并发下发。原自签名证书也随卷迁移；如果访问地址变化，应重新配置证书。Meraki快照恢复另见 [RESTORE.md](../RESTORE.md)。

## 11. 常见问题

| 问题 | 处理 |
|---|---|
| `docker: command not found` | 安装并启动Docker Desktop，或安装Colima与Docker命令行 |
| `Cannot connect to the Docker daemon` | 打开Docker Desktop或运行`colima start`，再确认`docker info` |
| `docker: unknown command: compose` | Homebrew用户改用`docker-compose` |
| 8443端口被占用 | 先确认占用程序，避免误停其它服务；本版本端口与Host校验绑定，不建议新手只改端口映射 |
| 网页刚启动打不开 | 等待容器healthy，确认使用HTTPS，再看容器日志 |
| 显示组织或网络未配置 | 检查是否首次启动前填写`.env`；老卷配置在`/data/config.json`，不是每次从环境变量覆盖 |
| 同一组织的网络名称填错 | 先备份并停止应用，再由管理员修改数据卷中config.json。切换组织/网络建议使用独立新项目与数据卷，不混用旧的规则归属 |
| 证书提示不受信任 | 默认是本机自签名证书；核对地址后处理信任，勿关闭API登录与来源校验 |
| 地址库或域名更新失败 | 检查到APNIC、GitHub和DoH服务的访问；看任务日志，恢复后手动重试 |
| API读取失败 | 检查Key权限、组织ID、网络名、来源白名单及公网连接 |
| 重装后密码变了或数据不见 | 核对Docker context和Compose项目目录；不同引擎或项目名使用不同的数据卷 |

## 12. 可选局域网 DNS

普通安装无需修改 DNS。若确实需要让其它终端使用此平台的DNS，请管理员检查Mac固定地址、53端口冲突和局域网访问范围，再按 [README的SmartDNS章节](../README.md#smartdns) 配置。

仅安装此平台**不会让国内/海外网页自动通过不同网络出口**。DNS分组与网络路由是不同功能，VPN和路由仍需由原有网络设施提供。
